## New feature: Medical History Report (consolidated PDF)

Goal: one button, one PDF the user can email themselves or share with a clinician. Includes narrative summary, charts, and clean tables of the underlying data. Generated server-side so the same PDF can be attached to email or stored.

### What goes in the PDF

Cover page
- Patient name (from profile), DOB, conditions, primary care contact (if set), date range, generated-on timestamp.
- "Generated by Purple — not a medical record" disclaimer footer on every page.

Sections (each starts on a new page, skipped silently when empty)
1. **Snapshot** — current meds list, active conditions, recent seizure count, adherence %, sleep/HRV/RHR baselines.
2. **Medications** — table: name, dose, schedule, start/end, adherence % over the window, last taken. Plus a small bar chart of adherence by week.
3. **Seizures / events** — table sorted desc: date, duration, type, triggers, notes. Monthly frequency bar chart.
4. **Biometrics trends** — line charts for sleep total, HRV, RHR, readiness/recovery, steps. One chart per metric, all sources overlaid (matches the dashboard). Each chart followed by a short "what this means" line.
5. **Lab reports** — the existing extracted lab values, latest values + trend arrows.
6. **Journal highlights** — AI-summarized top patterns/themes for the window (not raw entries — privacy).
7. **Aura events & hydration** — compact summary if user tracks them.
8. **Appendix** — raw daily biometric table for the window (small font), full med dose log.

### User flow

- New route `/reports/medical-history` with:
  - Date-range picker (presets: 30d / 90d / 6mo / 1y / custom).
  - Section toggles (all on by default; user can untick Journal or Appendix).
  - "Include charts" toggle (default on).
  - "Generate PDF" → spinner → download + "Share" actions:
    - **Download** — direct file.
    - **Email to myself** — uses existing transactional email pipeline.
    - **Share with care provider** — input email + optional message; emails the PDF as attachment and logs the share in a new `medical_report_shares` table.
    - **Share with caregiver in Purple** — picks from existing care relationships; drops a message into that care thread with the PDF link.
- Generated PDFs are stored privately in a new `medical-reports` storage bucket (private, signed URLs only). Listed under `/reports` alongside lab reports with a "My medical history" filter.

### How it's built

- **Server**: new `createServerFn` `generateMedicalHistoryReport` in `src/lib/medical-report.functions.ts`. It:
  1. Loads profile + meds + doses + seizures + biometrics + auras + hydration + lab reports + journal summary for the window (RLS-scoped via `requireSupabaseAuth`).
  2. Calls a server-only helper `medical-report.server.ts` that renders the PDF with **@react-pdf/renderer** (pure JS, works in the Worker runtime, supports charts via SVG). Charts are drawn as inline SVG (we already compute series client-side; we'll factor the math into `src/lib/biometric-series.ts` shared between dashboard and report).
  3. Uploads the PDF to `medical-reports/{userId}/{reportId}.pdf` via `supabaseAdmin`.
  4. Inserts a `medical_reports` row (id, user_id, window_from, window_to, file_path, sections jsonb, created_at).
  5. Returns a short-lived signed URL.
- **Sharing server fns**: `emailMedicalReportToSelf`, `emailMedicalReportToProvider(email, message)`, `shareMedicalReportInThread(threadId)`. All re-use existing email + care-chat infra.
- **DB migration**: add tables `medical_reports` and `medical_report_shares` with RLS scoped to `auth.uid()`, plus a new private `medical-reports` storage bucket with owner-only RLS.

### Out of scope / explicit no-go

- No FHIR export, no CCD/CDA, no clinician portal. Just a well-written PDF.
- No automatic scheduled reports yet (can add later).
- No editing of generated PDFs.

### Order of work

1. Migration + bucket + types.
2. Shared series math in `biometric-series.ts`.
3. PDF renderer (`medical-report.server.ts`) with sections + charts.
4. `generateMedicalHistoryReport` serverFn + `/reports/medical-history` page (download only).
5. Email-to-self, email-to-provider, share-in-thread.
6. Listing under `/reports` with re-download via signed URL.

Then we're done.
