
## Goal

Move Purple from a hand-curated list of 10 conditions to a real **condition platform**: ~40 well-supported chronic conditions, with each user getting a personalized experience generated by AI on top of a structured medical taxonomy — not 40 copies of hardcoded prompt arrays.

## Design principles

1. **Data, not code.** Conditions live in a DB table with structured metadata, not as a hand-written object in `condition-prompts.ts`. The frontend code reads from the taxonomy, so adding the 41st condition is a row, not a release.
2. **Traits over labels.** Features (seizure log, glucose trend, pacing tools, mood check-in, BP trend, etc.) attach to **traits** ("seizure-prone", "glycemic", "autonomic", "inflammatory", "neurodevelopmental", "pacing-required"…). Each condition maps to 2–5 traits. ~12 trait modules cover all 40 conditions — no combinatorial explosion.
3. **AI personalizes once, then caches.** We don't call the LLM on every page load. On onboarding (and whenever conditions change), a server function generates a **Care Profile** for the user — stored in `profiles.ai_care_profile` (jsonb). Today/Journal/Ask Purple read from that cached profile.
4. **Calm, never clinical.** Same disclaimer rules. No diagnosis, no thresholds presented as advice. Red-flag symptom copy routes to "this sounds like it needs a clinician now".
5. **Brand intact.** PURPLE wordmark untouched. Account menu top-right. No new analytics.

## Architecture

### 1. Condition taxonomy table (`condition_catalog`)
Seeded, read-only for users. Per row:
- `slug` (text, PK) — e.g. `autism`, `epilepsy`, `t2_diabetes`
- `label`, `short_label`, `aka` (synonyms)
- `category` (neuro, mental_health, autoimmune, …)
- `traits` (text[]) — e.g. `["neurodevelopmental","sensory","routine-sensitive"]`
- `common_symptoms` (text[]), `common_meds` (text[]), `key_metrics` (text[])
- `monitoring_cadence` ('daily'|'weekly'|'asneeded')
- `red_flags` (text[]) — symptoms that should nudge "see a clinician"
- `evidence_refs` (uuid[] → `research_sources`)
- `disclaimer_tier` ('general'|'sensitive') — e.g. mental health gets softer copy

### 2. Trait module registry (code)
`src/lib/condition-traits.ts` defines ~12 traits. Each trait owns:
- Default features it turns on (`feature-catalog` keys)
- A set of journal prompt **templates** (parameterized: `{symptom}`, `{med}`)
- Ask-Purple question templates
- Tip categories to draw from
- Today greeting tone modifiers

A condition's experience = union of its traits' modules + condition-specific overrides from the catalog. No more `Record<ConditionTag, string[]>` blocks per surface.

### 3. AI Care Profile (the personalization layer)
New server function `generateCareProfile.functions.ts` using Lovable AI Gateway (`google/gemini-3-flash-preview` by default, structured output via `Output.object`):

Inputs: active conditions (+ archived, family history), `conditions_note`, age/sex/timezone from profile, top meds, recent journal sample (last 14 entries, content only).

Output (cached in `profiles.ai_care_profile` jsonb):
```
{
  version: 1,
  generatedAt, conditionsHash,
  todayGreeting: { morning, afternoon, evening },
  journalPrompts: [6 personalized prompts],
  askPurpleStarters: [5 questions],
  dailyTipPool: [10 short, evidence-light tips],
  watchFor: [red-flag phrases to scan for in journal entries],
  trackerSuggestions: [feature keys to recommend],
  toneNotes: "calm + low-energy, this user is in a flare phase"
}
```

Regenerates when: conditions array changes, every 30 days, or user clicks "refresh my experience" in Settings → My Health. Falls back to trait-derived defaults if AI call fails or credits exhausted (graceful degradation — the app still works without the LLM).

### 4. Per-condition deep page
New route `/_app/my-health/$conditionSlug` for each active condition:
- What Purple tracks for this (from traits)
- Personalized notes from the Care Profile
- Recent related journal entries (semantic match via existing `ai_memory` embeddings)
- Linked evidence cards from `research_sources`
- Toggle trackers, archive, or mark in remission

### 5. Onboarding flow upgrade
- Search-first picker over the 40 conditions (with synonyms, e.g. "ASD" finds Autism)
- After selection, show "We'll turn these on for you" trackers sheet (existing `EnableTrackersSheet`, but driven by traits)
- Background: kick off Care Profile generation; show optimistic defaults immediately

### 6. Journal & Ask Purple integration
- Journal new-entry prompts come from `ai_care_profile.journalPrompts`
- Today greeting + tip card read the cached profile
- Ask Purple system prompt includes the condition catalog rows for active conditions + the Care Profile's tone notes
- Journal extraction (existing `journal-classify.functions.ts`) gets condition-aware behavior taxonomy (e.g. sensory overload events for autism, PEM events for long COVID)

### 7. Safety rails
- Every AI-generated surface keeps the medical disclaimer footer
- `watchFor` red flags trigger a calm, non-alarming "this might be worth a clinician call" inline note in the Today view — never autoblock the user
- Sensitive conditions (eating disorders, suicidal ideation context) use the `sensitive` disclaimer tier with crisis resources

**Wave 4 (Journal intelligence)** — condition-aware behavior extraction, red-flag scanning with calm clinician nudges.
