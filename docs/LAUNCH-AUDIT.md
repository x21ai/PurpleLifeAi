# Launch Surface Audit

Date: 2026-06-12. Every user-facing route graded for launch readiness. Grades reflect what a stranger hits via nav, onboarding, or marketing links.

- **A** = polished, works end to end, copy in voice, ready for a stranger
- **B** = functional but rough (copy, edge cases, empty states)
- **C** = scaffolded or unfinished

Dark-launch action taken in this PR: every peripheral route graded B or C is now behind an `app_settings` feature flag, default OFF (see "Feature flags" below). Core-loop routes were never flagged.

## Feature flags added (dark launch, default OFF)

New boolean columns on the `app_settings` singleton, super-admin editable, anon-readable like `pro_free_for_everyone`:

| Flag                        | Routes gated                                                                 | Nav/links hidden                                |
| --------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------- |
| `feature_community_enabled` | `/community`, `/community/$postId`, `/community/resources`, `/community-new` | Sidebar "Community" item, footer Community link |
| `feature_dna_enabled`       | `/my-health-dna`                                                             | Insights > DNA nav leaf                         |
| `feature_friends_enabled`   | `/friends/$friendshipId`, `/friend/join`, `/friend/accept`                   | (no nav entries exist)                          |

Deliberately not flagged: `/admin/*` (already role-gated and invisible to non-admins; flagging it off would lock out operators) and `/features` (a marketing nav page whose gap is one copy block, fixed in the copy sweep rather than hidden).

To light a feature up: `UPDATE app_settings SET feature_community_enabled = true WHERE id = true;` (or via the admin billing settings surface pattern).

## Needs human decision (core-loop, functional gaps)

1. **`/my-health`**: the "My Body" sidebar destination shows fabricated health data (mock readiness, fake dates). Highest-impact launch risk: a stranger will think the app is broken or dishonest. Options: build the real hub (16-24h), or redirect to `/biometrics` and drop the group landing page (2-4h). Recommendation: redirect now, build later.
2. **`/vitals`**: orphan mock page. Options: build real vitals UI, merge into `/insights`, or remove the route. Recommendation: redirect to `/insights` until built.
3. **`/meds/$medId` interactions stub**: visible "we're working on it" block for every med user. Options: ship the stub honestly, hide the section, or build interaction warnings (8-16h). Recommendation: hide the section pre-launch.
4. **`/tools` dead "Set up a new device" button and hardcoded battery ring**: remove or implement. Recommendation: remove both pre-launch.

These are deliberate product calls and are not changed by this PR. `/welcome` landing on marketing instead of `/today` is also functional but is fixed by Workstream C (onboarding rework).

## Cross-cutting notes

- AI surfaces degrade gracefully (calm stream errors, quiet empty cards); the one wrong AI story is the `/features` marketing copy (Workstream E).
- Voice is strong on marketing, auth, Today, journal, care. Rough: admin (acceptable), and the mock `/my-health` + `/vitals` pages which read like a different product.
